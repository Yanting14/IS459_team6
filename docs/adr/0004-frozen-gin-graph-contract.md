# Preserve the selected GIN contract and derive daily account rankings

The selected IBM GINe checkpoint consumes 35 transfer-edge features, 30 account-node features and graph connectivity. The existing seven-day account-day features cannot substitute for these inputs. Keep both representations and use the saved dictionaries/scalers without refitting.

GIN snapshots contain cumulative observations from 1 September 2022 up to an exclusive cutoff. Preserve self-transfers, parallel transfers, original received amounts/currencies, original source-row order for timestamp ties and the saved node map. New accounts append to the map. This supersedes any interpretation of ADR-0002 that every model must consume `build_features` output; it preserves separate labels and one implementation per feature contract across visibility views.

First reproduce the historical evaluation-window ranking at K=1,000. Daily scoring uses one midnight-to-midnight target window and its ending cutoff, with all earlier context available. Daily eligibility requires a non-self transfer that day. An eligible account's score is its maximum incident transfer score, including self-transfers. Highest-score evidence ties use the smallest original source-row ID; account-score ties use saved node ID. A daily review budget is an explicit argument, not an inference from the historical K. Daily performance must be measured separately.

Filter bank visibility (sender OR receiver bank) before graph features and indexes are constructed. Restrict review eligibility to the bank's own accounts for Q2; use the same cohort, windows, budget, weights and scalers in both views. Do not reuse shared node summaries for bank scoring.

Curated v2 preserves checksum-qualified source-row transfer IDs and separate transfer labels. Raw files are unchanged. The adapter handles one source snapshot at a time, using disk-backed joins and sorting to stage Parquet as memory-mapped numeric arrays. It is a single-node implementation. Cloud orchestration uses one Batch CPU job after Prepare so graph arrays remain on local scratch storage between stages. Full-data benchmarks and the successful cloud acceptance run support a 4-vCPU, 16-GiB worker; daily evaluation results are recorded in [scoring validation](../scoring-validation.md). The worker can read transfers and the model bundle, but has no access to label objects. A content-keyed gold completion manifest publishes one attempt atomically; concurrent or interrupted attempts cannot mix their output files. The image is pinned by digest, and scoring stays disabled during artifact bootstrap.
